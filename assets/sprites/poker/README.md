# DeetsPoker sprites

Two sets, drawn independently: the **chips** (below) and the **card
back** (bottom of this file). Both are probed once at page load and swap
in over their CSS placeholder the moment the file exists.

## Chips

Edge-on chip art for the poker tab (docs/poker.md, "Chips on the table").
A stack is one **side** sprite per chip, tiled the whole way up. There is
deliberately **no top-of-stack face sprite** — a face capping a column of
bands read as odd (his call, chat 2026-08-03), so every chip in a stack
is the same side view.

`poker/poker.js` probes all five files ONCE at page load and swaps art in
over the CSS placeholder the moment a file exists — draw over these
templates one at a time and only that chip changes. Deleting a file falls
back to the placeholder for that rank.

## Naming scheme (exact, all lowercase)

| file | chip |
| --- | --- |
| `chip-side-{1..5}.png` | one chip, edge-on: the band |

**The number is the chip's RANK in the ladder, not its value.** Values are
derived from the buy-in (docs/poker.md, "The settings cascade") — a $20
table's rank-1 chip is 10¢ and a $100 table's is 50¢ — but rank 1 is
always the smallest chip on any table, and always white. That is what
makes these filenames stable. Ranks 6-8 exist only on a hand-built ladder
and keep the CSS placeholder.

Rank colors (`RANK_HEX` in `poker/transport-mock.js`), if you want to stay
on palette:

| rank | color | hex |
| --- | --- | --- |
| 1 | white | `#f2efe6` |
| 2 | red | `#d94141` |
| 3 | green | `#2fae66` |
| 4 | blue | `#3b7dd8` |
| 5 | black | `#26221f` |

## Canvas

Templates are **96 × 24** — 4× the 24 × 6 the rail draws at, 6× the
felt's 16 × 4. As with the mahjong tiles the page downscales with plain
smooth filtering (**no `image-rendering: pixelated`** — at fractional
sizes nearest-neighbor makes identical chips shimmer against each other,
and a stack is nothing but identical chips), so ship at 4× and it stays
crisp at both sizes and on HiDPI.

Draw the WHOLE chip — band, spots, edges — the image fully replaces the
placeholder's styling. The sprite **tiles vertically**, so its top and
bottom edges must meet cleanly: whatever you draw on the very top row
sits directly against the bottom row of the chip above it. A stack is
this one image repeated, nothing else.

The templates are generated by `scripts/build-poker-chips.py`
(**re-running it RESETS the chips** — don't, once hand art has landed).

# The card back

| file | what |
| --- | --- |
| `card-back.png` | the back of a playing card |

**One image, every face-down card on the page.** The deck in front of
the button, the burn pile beside the board, a hand being pitched, a hand
being mucked — all of them are this file, because all of them are the
same card seen from the same side. Draw it once and they all change.

There is **no card FACE sprite and there won't be one.** A face is its
rank and suit set in the page's own type (`poker.js` `cardEl`), so it
follows the theme and the skin like every other piece of text — and 52
hand-drawn faces is not a reasonable thing to sign anyone up for.

## Canvas

**208 × 288** — 4× the largest size the page draws a card at (the hand
panel's `.pk-card--big`, 1.5× the felt's `--pkcardw` × `--pkcardh`). Same
rule as the chips and the mahjong tiles: the page downscales with plain
smooth filtering, **never `image-rendering: pixelated`**, so ship at 4×
and it stays crisp at every size and on HiDPI.

Draw the WHOLE card — corners, border, pattern. The sprite replaces the
placeholder's weave and its border outright (`.pk-card--back.is-art`
clears both), so nothing of the CSS card shows through. Unlike the chip
band this one does **not** tile: it is one card, drawn once, and its
edges meet nothing.

Palette, if you want to stay on it: the weave is `--pkback` `#7a3535`,
the border `--pkfelt-edge` `#26443a`, the pale inset rim `--pkface-edge`
`#d9cfae`.

The template is generated by `scripts/build-poker-cards.py`
(**re-running it RESETS the card back** — same warning as the chips).
